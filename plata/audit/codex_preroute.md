# Предварительная разводка МСО74 — Codex

## Итог

**Задание выполнено частично. Эту ветку нельзя считать готовой предварительной разводкой для автоматического продолжения.**
Сделаны локальные силовые соединения, USB на F.Cu, кварцы, тепловые переходы и большая часть служебного веера U22.
Из 11 сегментов Ethernet-пар завершён один; вывод питания ядра U22.41 и пять соединений обвязки PHY остались неразведёнными.
DRC: новых геометрических ошибок нет; остаются 4 известные `hole_clearance` J5, 3 новых предупреждения `copper_sliver` B.Cu и общие неразведённые связи.
Скрипт сохраняет частичный результат и JSON, затем возвращает код **1**. Вызов в workflow поэтому останавливает автоматическое продолжение до завершения ответственных узлов.

Основание: `main` **9d950f98494b11c436177db119357004fd8a3197**, ветка работы `route/preroute-codex`.
Плата **240 × 120 мм, 4 слоя, 1,6 мм**; целевой стек — **JLC04161H-7628** из задания.
Проверка выполнена локально в **KiCad 9.0.2**, через `pcbnew` и `kicad-cli`.
Схема и её генератор не изменены. Исходный нетлист экспортирован из схемы main; позиции, корпуса и назначения выводов совпали с CI `kicad-out` (955cdec, исходник 9d950f9).
Координаты ниже — из `placement.json`; в файле платы к ним прибавлено **(30; 30) мм**, как в `pcb_build.ORIGIN`.

### 1.2. Ethernet и USB

Длины — по центральным линиям меди **между указанными контактами**, без приписывания длины непроведённым участкам.
Для пары Ethernet включены её короткие выходы из площадок; боковые ветви терминации не считаются частью основного тракта.

|---|---|---|---|
| USB J5 B6/B7—USBLC6 | 0.29/0,20 | 5.948698 / 5.948698 | 0.000000 |
| USB-C A6/A7—B6/B7 copies | 0,15; fanout | 3.030000 / 3.070000 | 0.040000 |
| USB USBLC6—CH340K | 0.29/0,20 | 17.203036 / 17.034894 | 0.168142 |

Основные USB-пары имеют **0,29/0,20 мм на F.Cu**. У контактов USB-C начальный выход **0,15 мм**, чтобы соблюсти зазор до соседнего NC-контакта; две короткие перемычки копий также 0,15 мм.
Копии A6/B6 и A7/B7 соединены **целиком на F.Cu, без переходов**: DP обходит площадки справа, DM слева. Главная пара выходит с B6/B7.
При второй ориентации кабеля к соответствующим проводам добавляются **3,03 / 3,07 мм**. Для B6/B7 суммарные длины до CH340K **23,151734 / 22,983592 мм** (перекос **0,168142 мм**); для A6/A7 — **26,181734 / 26,053592 мм** (перекос **0,128142 мм**).
Пара у CH340K огибает его GND EP сверху и подходит к USB-площадкам со стороны корпуса; через EP не проходит.
Короткие разветвления USB-C и fanout у выводов **не заявляются участками с контролируемым импедансом 90 Ом**; W/S задаётся на связанных магистралях. Проверка импеданса полевым решателем/измерением не выполнялась.

Ethernet W5500 TX → T1 выполнен **0,24/0,20 мм F.Cu**; на выходах из мелких площадок применены neck **0,15 мм**. Для обоих проводников найден общий коридор, затем построены параллельные смещения; длина согласована в fanout.
Остальные Ethernet-пары не закреплены: скрипт удаляет целую неудачную попытку, включая уже созданный первый проводник. Проект не содержит половины пары, выданной за завершённую.

Средние точки выполнены частично: T1.7 → C66/R51/R52, T2.2 ↔ T2.7 → C85, J7.4 ↔ J7.5 → C67 и J18.4 ↔ J18.5 → C109.
Часть подводов получилась длинной из-за размещения C67/C109; требование «средние точки коротко» **в полном объёме не выполнено**. Пять неподключённых ветвей перечислены ниже.
Цепи экранов/Bob Smith `ETH_SH1` / `ETH_SH2` к C112/C114 ∥ R115/R118 не завершены. Прямого обхода этих RC на GND скрипт не создаёт.

### 1.3. Кварцы

XI/XO всех трёх генераторов и нагрузочные элементы, включая площадку DNP C81, соединены на **F.Cu, 0,15 мм**. Y1 перенесён к правым выводам XI/XO W5500; Y2 — к выводам PCF8563; Y3 отодвинут от северного ряда U22 для веера.
Y1/Y3 и конденсаторы используют общую GND со сшивкой в In1; отдельного разрыва земли не сделано.
Кварцевые цепи U22 проложены до веера: XI не пересекает по диагонали поле CORE/IBREF, XO обходит GND-площадку кварца справа.

### 1.4. Земля и тепло

- Добавлено **350 GND-via**, включая локальные возвраты, периметр и тепловой массив.
- Под **U22 EP49** подтверждено **9 via 0,45/0,20 мм**, сетка 3 × 3 с шагом 1 мм, и локальная GND-медь B.Cu. Массив создаётся **до** B-трасс служебных цепей, иначе они занимали места отверстий. Контроль наличия всех девяти обязателен и выполняется скриптом проверки.
- **15 PTH EP21 U1 сохранены**. Добавлена локальная GND-медь B.Cu; дополнительные отверстия в этот массив не вставлены.
- У U5/U6 переходы земли относятся к **PGND9/11 и AGND3**, а не к SW10. Проверка не обнаружила GND-via, пересекающих SW land.
- Период сшивки вдоль кромок — 8 мм. Если точка занята, она смещается по нормали к кромке. Измеренные максимальные расстояния между соседними шовными via: **top 8.000, bottom 8.010, left 8.000, right 9.009 мм**; каждое не более 10 мм.
- По имени цепи `GND` подключены только площадки этой цепи. Контакты экранов RJ45 остаются `ETH_SH*`; их изоляция не обходится.
- Отверстия тепловых массивов не означают автоматически заказ via filling. Перед производством нужно согласовать тентирование/технологию и окно пасты EP с JLCPCB. Реальные температуры кристаллов и нагрев меди здесь не измерены.

### 1.5. Веер U22

Выходы служебных цепей выполнены **0,15 мм F.Cu** к смещённым via **0,45/0,20 мм**, затем по B.Cu к реальным цепям назначения либо через In2 +3V3.
Для CORE проведены также связи C86–C96; для RST/LED/IBREF — к R113/C106, R54, R114 и R112 соответственно.
Простое чередование радиусов без разведения направлений не подходит: via при шаге 0,4 мм нарушал бы зазор до соседнего длинного ствола. Поэтому окончания раздвигаются вдоль ряда, а северные CORE/IBREF имеют явные координатные рецепты.

**U22.41 (SW_VCORE) не выведен.** Текущему алгоритму не удалось завершить этот выход между кварцевыми связями, IBREF и соседними CORE-переходами. Это требует ручного маршрута или изменения рецепта.
MDI-площадки не переводятся на B.Cu ради искусственного уменьшения числа незавершённых связей; их незаконченный выход относится к недостающим Ethernet-парам.

## 2. Что не сделано и почему

Следующие **16** попыток прямо отмечены в манифесте. «Нет коридора» означает отказ данного ограниченного локального поиска, **не доказательство физической невозможности развести плату**. Замкнутый/пересекающийся offset, недопустимый fanout или несогласованный маршрут не сохраняются.

- `fanout U22.41`.
- `ETH W5500 RX—C64/C65 (нет общего коридора)`.
- `ETH C64/C65—T1 (offset/clearance)`.
- `ETH LNK_A T1—T2 (fanout)`.
- `ETH LNK_B T1—T2 (fanout)`.
- `ETH RTL port0 TX—T2 (нет общего коридора)`.
- `ETH RTL port0 RX—T2 (нет общего коридора)`.
- `ETH RTL port1 RX—J7 (нет общего коридора)`.
- `ETH RTL port1 TX—J7 (нет общего коридора)`.
- `ETH RTL port2 TX—J18 (нет общего коридора)`.
- `ETH RTL port2 RX—J18 (нет общего коридора)`.
- `T1.2—C63.1`.
- `T1.2—R50.2`.
- `T1.6—R51.1`.
- `T1.8—R52.2`.
- `U10.2—R48.1`.

Для завершения Ethernet нужен пересмотр взаимного расположения/ориентации T1/T2 и направления выходов W5500/U22, либо ручная прокладка пар с контролем зазора и длины. Зафиксированный TX W5500 занимает часть доступного коридора RX; автоматически разрывать уже закреплённую пару скрипт не пытается.
Цепи средних точек и терминации следует завершать одновременно с парами, а C67/C109 и экранные RC — приблизить к соответствующим контактам разъёмов после проверки куртьярдов.

Также **не заявлены выполненными**: все общие сигналы, полностью малоточная обвязка питания, терминация экранов, электрическая/тепловая верификация на реальной плате, проверка SI/импеданса решателем, полный прогон Freerouting 2.5.0 нового DSN.
Это объясняет наличие общих неразведённых связей; оно не заменяет список недостающих ответственных участков выше.

## 4. Изменения интеграции

- `pcb_preroute.py` запускается после `init`. Повтор на уже обработанной плате отвергается, чтобы не дублировать медь; повтор на свежей плате детерминирован.
- В `route.yml` добавлена **ровно одна строка** вызова. Из-за незавершённых ответственных соединений `preroute` сейчас возвращает **1 после сохранения** платы и `.preroute.json`; штатный `set -e` не пропускает это состояние в автотрассировку.
- В `pcb_route.export` необходимо сохранить закреплённые наружные силовые зоны и цепи, начатые только зоной. Обычные наружные GND-заливки по-прежнему удаляются только из временной экспортной копии.
- KiCad DSN экспортирует границу зоны, а не результат её обтекания площадок. Поэтому закреплённые зоны передаются **по filled-контурам с отверстиями**, а не исходными прямоугольниками, захватывающими чужие площадки. Каноническая плата при экспорте не перезаписывается.
- В `pcb_rules.py` fine via внесён и в меню размеров, и как предпочтительный via классов ETH/USB. **Силовые классы сохранили 0,60/0,30**. Дорожки и зазоры существующих классов не уменьшались.
- Схема, её генераторы, BOM, DESIGN.md и прежние аудиты не правились.

## 7. Как воспроизвести

Нужны KiCad 9 с `pcbnew`, актуальные footprint-библиотеки проекта и пустая рабочая папка. Локально использован снимок `kicad-libs` **2147e8cb3d3531e21ecf17bce98427b1ee6e3ddf**, системный MountingHole_3.2mm_M3; проектные библиотеки не менялись. KiCad 9.0.9 из CI отдельно не запускался.

```sh
mkdir -p /tmp/mso-preroute
kicad-cli sch export netlist --format kicadsexpr --output /tmp/mso-preroute/main.net plata/kicad/mso74-plata.kicad_sch
python3 plata/kicad/gen/pcb_build.py /tmp/mso-preroute/main.net plata/kicad/placement.json /tmp/mso-preroute/board.kicad_pcb
python3 plata/kicad/gen/pcb_route.py init /tmp/mso-preroute/board.kicad_pcb
python3 plata/kicad/gen/pcb_preroute.py /tmp/mso-preroute/board.kicad_pcb
# Для этой версии ожидается код 1: частичная плата и board.preroute.json уже сохранены.
kicad-cli pcb drc --format json --severity-all --output /tmp/mso-preroute/drc.json /tmp/mso-preroute/board.kicad_pcb
python3 plata/kicad/gen/pcb_route.py export /tmp/mso-preroute/board.kicad_pcb power /tmp/mso-preroute/power.dsn
```

Файл `verification.json` описывает именно приложенный проверенный результат. Предупреждения SWIG/геометрической библиотеки при DSN-экспорте KiCad 9.0.2 не скрывались; DSN получен и разобран проверяющим скриптом. Поведение полного Freerouting с этими plane-областями остаётся непроверенным.
